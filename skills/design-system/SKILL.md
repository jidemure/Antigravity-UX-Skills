# Design System

Inspect stylesheets, theme configuration, shared components, and several representative screens. Document existing decisions rather than inventing a replacement. Create or update root DESIGN.md with: color roles and values; typography families/scales; spacing scale; layout/breakpoints; radius, border and elevation rules; icon-family conventions (stroke weight, size, alignment, and when accent color is allowed); component patterns; interaction/focus/motion conventions; and known exceptions. Prefer references to source tokens over duplicated values. Note uncertainty when evidence is incomplete. Then apply the documented system consistently to requested UI and avoid unrelated rewrites. If no system exists, propose a minimal coherent set grounded in the product context and implement tokens in the project's native mechanism.
